# Loading and responsiveness — verified changes, 2026-09-13

The largest confirmed costs were the unoptimized hero image, browser font transfer, unnecessary logo-renderer initialization, foreground diagnostics writes, and an extra catalog streaming boundary. The fixes are live on [atehna.vercel.app](https://atehna.vercel.app) and [www.atehna-test.site](https://www.atehna-test.site), deployment `dpl_2BrjfBpMwhyVWz9jwrzZv4btHFxg`. Production promotion and smoke verification completed on 2026-09-13 at 13:04 UTC. Warm requests and transfer improved; a slow first request remains, detailed below.

## Setup and method

Next.js 16.3.1 / React 19.2.5, App Router, Node 24.13.0. The root remains dynamically rendered. Database access uses pg Pool (max 10, idle 10 s) and the existing 60-second tagged read cache/invalidation. Vercel runtime functions originally ran in iad1; the final deployment is verified fra1, matching the linked production Neon and Blob resources. [Infrastructure evidence](infrastructure-2026-09-13.md) distinguishes resource metadata from the inaccessible exact connection hostname.

Browser measurements: Chromium 145.0.7632.6, 1440×1000, reduced motion, same Windows host. Each route sample contains one fresh-browser visit and two repeats. “First visit” does not prove a Vercel or Neon cold start. TTFB below means final response headers; HTTP 103 informational responses arrived much earlier. Local comparisons use production builds and the same isolated database: 44 catalog items, 14 categories, 2 total orders. The default orders view is empty, so its result is a shell/authentication observation. Production exposes 40 product links; the before/after links and text match exactly.

The controlled homepage test uses a warmed application, three fresh/repeat browser pairs, 10 Mbps down / 5 Mbps up / 40 ms configured latency, and no CPU throttling. Final local measurements ran with one server; it was stopped before the final isolated browser suite. Production and local datasets/assets are reported separately.

## Navigation, outliers and remaining delay

The original ~870 ms automated navigation readings overstated actual rendering: a verified React 300 ms Suspense commit throttle delayed some updates, then Playwright selector polling added roughly 500 ms. Final measurements use actual click events, MutationObserver and a paint opportunity instead. Actual production click→detail paint opportunity improved from a median 527 to 430 ms over three transitions per deployment. Final local click→paint was 345.5 ms initially and 46.2 / 46.7 ms on repeats, with RSC completion 5–9 ms. In the final production trace, RSC headers arrived at a median 79 ms and response/abort end at 115 ms; these requests were marked ERR_ABORTED, so 115 ms is not a complete-stream duration. The target heading appeared correctly in all three transitions, without browser exceptions or long tasks. The retained child loading boundary can still trigger the framework throttle. This is distinct from the removed full-catalog boundary.

The first homepage request immediately after promotion was worse than the original first sample: final headers 1,288 → 4,675 ms and LCP 1,728 → 5,432 ms. Of that final request, 2,282 ms elapsed before DNS began and 2,209 ms elapsed between request dispatch and final headers; the optimized hero request then took 726 ms. Repeat LCP was 324 and 188 ms. The original first request had a 1,206 ms dispatch-to-final-header wait. This comparison does **not** demonstrate improved cold-start performance.

The repeated approximately 2.28 s pre-DNS delays also occurred on preview and the original production deployment, so that portion is browser/network startup. The remaining 2.21 s server/network wait after promotion is significant and unexplained. Final live listing headers ranged 152–464 ms; later old-production product-detail requests had reached 1.06–1.10 s. Available telemetry cannot reliably separate function startup, Neon wake-up/connection time and individual database phases for those outliers. A fresh browser visit does not establish database suspension or a cold function.

Exact next diagnostics: renew Neon CLI access with `neon auth --profile DEFAULT`, inspect production endpoint compute/suspension and query metrics, and correlate first/warm function requests. Speed Insights reports no data; Vercel aggregate observability queries require an unpaid-for upgrade. Vercel sensitive environment values cannot be read back, even after the user's bounded permission, so no production credential was returned or persisted. Production admin timing also needs an authenticated application session.

Some product-detail visits still show approximately 300 ms between completed data delivery and reveal; revisiting the retained child loading/prefetch boundary would require the same state/freshness checks. Existing orders CLS ≈ 0.093 and small product-image shifts remain. Homepage controlled CLS stayed ≈ 0.00017 fresh/0 repeat. No database capacity, suspension policy, pool size or freshness rule was changed without evidence.

## Functional, visual and resource checks

Production build/full TypeScript, lint, schema-file contract and all 1,723 unit/contract tests pass on the final source. An earlier full 311-case browser run passed. The final isolated full run was **303 passed, 2 failed, 6 skipped**. Focused follow-ups passed **13/13 and 6/6**, with each focused inventory verified; the coverage audit confirms **311 distinct cases with passing results, zero missing/unexpected cases**. This is not a single clean 311-case run. Storage database regression passed 1/1.

One failed test filled a message 14 ms after Escape, before the datepicker's scheduled return-focus frame; the test now waits for dialog closure and that frame, then asserts focus before typing. It retains all existing value/notice assertions. The other failure involved keyboard opening of the mobile navigation font selector; its entire 10-case file passed unchanged in the focused run. A focus-induced scrolling race is plausible but not proven. The six skipped serial order/quote cases all passed explicitly. Original failures, focused results and the distinct-case coverage audit are retained. No navbar/product behavior was changed to make these tests pass.

Desktop/mobile hero, navbar and text geometry and page heights match. Outside the compressed hero, mobile pixels matched exactly; desktop differed by 10 of 1,154,880 pixels. Hero mean channel error was 0.94/255 desktop and 1.65/255 mobile. Carousel and desktop/tablet/mobile editor-preview checks pass. Existing coverage exercises auth/revocation, immediate saved changes, stock/prices/checkout, filtering/selection/export, logo publication/PDF pixels and navbar contracts.

The six WOFF2 assets add 995,224 B static storage while reducing browser transfer. Vercel reports a 33.49 MB function package versus 32.38 MB before; deployment package size therefore did not decrease despite the measured lower module initialization cost. Image transformations add work on a first size/format request and reuse the existing image cache. Diagnostics retain equivalent database writes after response. There is no new keepalive, polling, speculative-prefetch loop, replica, larger compute setting or paid upgrade. Regional billing differences have not been measured.
