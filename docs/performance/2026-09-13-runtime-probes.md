# Bounded production request timings

The second-pass instrumentation is disabled unless the deployment sets `ATEHNA_PERFORMANCE_DIAGNOSTICS=1`. Disabled deployments keep the original pg Pool and skip the Node tracing SDK registration import. It does not change page dynamic/static configuration, SQL, connection policy, query results, auth, cache callback identity, keys, tags, TTL, invalidation timing, or layout concurrency.

With the flag enabled, only a W3C `traceparent` whose trace ID starts with `a7e4a001` and whose sampled flag is `01` is recorded. Example shape: `00-a7e4a001<24 random lowercase hex characters>-<16 random lowercase hex characters>-01`. Use a new ID per HTTP request, and retain it in the client timing record. Normal traffic produces no new per-query logs. Each instance admits at most 60 probes/minute, retains at most 32 active traces and 128 phase records/trace, and evicts stale traces after 120 seconds when another probe is admitted. Up to 128 completed IDs remain for the same short window so late framework children cannot reopen an emitted trace.

The official Next 16.3.1 OpenTelemetry integration preserves the same trace across framework and application work. The instrumentation reads no component cookies or headers and therefore does not force the homepage dynamic. Existing helpers register one Next `after()` callback per trace, which emits a bounded `console.info(JSON.stringify(summary))` line after response completion. It neither inserts diagnostics rows nor waits for an external exporter. If there is no request lifecycle, it does not fall back to a foreground log. Existing legacy diagnostics persistence remains separate, scheduled after the response, and is excluded from these DB phase measurements.

The log event is `atehna.runtime-timing.v1`; `traceId` matches the probe. `instance` contains a random process-local instance ID, registration time, measured registration duration and Vercel runtime region. `firstProbeOnInstance` means first completed probe, not first HTTP request or proof of a platform cold start. The same-runtime metadata is also available at the existing authenticated `/api/admin/analytics/diagnostics?runtime=1` endpoint with private/no-store caching. Unauthorized users still receive the existing authentication rejection.

`database.hostname` and `port` are read from the instantiated pg Client after pg merges connection-string query fields and PG environment fallbacks. The response also reports effective numeric pool/timeout settings, TLS flags, and only the names of recognized present environment overrides. It does not return a connection string, username, database name, password, certificate, SSL key, PG options, SQL, parameters, rows, HTTP target/full URL, headers, or exception messages/stacks. Framework route patterns and a small allowlist of timing fields are copied; arbitrary span attributes are never serialized.

| Phase/field | What it measures | Limitation |
| --- | --- | --- |
| instance.registrationMs | Instrumentation registration, including its dynamic Node SDK import | Excludes earlier platform/process provisioning; compare identically instrumented deployments |
| pool.acquire | Time from checkout request until pg returns a client/error | Counts expose initial total/idle/waiting clients |
| db.connect | New client connect callback interval: DNS, TCP, TLS, auth combined | Neon activation may be inside this interval; not separately measured |
| waitAndCheckoutMs | Acquire interval less an observed new handshake | Includes checkout scheduling; absent on failed acquisitions when the handshake is unobserved |
| db.query | Driver query invocation to result/error | Includes client query queue, network, server work and locks; these are not split |
| cache.lookup | Existing unstable_cache call duration | Does not assert hit vs stale; preserves original callback and key |
| cache.refresh | Existing catalog cache callback actually executed | A stale refresh can overlap or outlive the response; shared-setting cache status is not guessed |
| app.dependency | Named existing shell/homepage Promise.all branch | Branches overlap; do not sum as wall time |
| app.route/app.loader/app.* | Existing application data/JSX/phase helper duration | Returning JSX is not completion of React rendering |
| next | Allowlisted Next request/render/metadata/fetch/module spans | Missing/unfinished framework spans are not invented; fetch URLs are omitted |
| throughAfterMs | Collector admission until its after-response snapshot | Server lifecycle elapsed time, not browser TTFB or paint |

Requests served entirely from the CDN may have no runtime trace. Use response cache headers and client timings to identify that condition. A missing trace is not a zero-millisecond server measurement. Browser actionability, React transition scheduling, final DOM/paint, actual Neon endpoint status/operations and lock waits require their own correlated evidence. Failed/aborted requests must remain separate from completed navigation timings.
