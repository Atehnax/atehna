# Playwright E2E coverage and layer audit

Date: 2026-08-17

This document inventories every current case under tests/e2e and tests/unit after the conservative browserless migration, including the two generated viewport cases from product-detail-compactness.spec.ts. It is a coverage audit, not permission to weaken or remove currently failing tests. All 88 migrated unit cases retain their audited test titles and assertion logic; they were moved out of Playwright collection, not deleted. Twenty-three additional unit cases add twelve E2E Blob/database/cache-teardown and production-storage safety checks, one storefront-ordering behavior check, one product-detail route-cache regression contract, four order-submission latency and recovery contracts, and five order-access transport-security contracts.

## Summary

- 30 E2E spec files contain 118 test declarations and generate 119 Playwright cases.
- Every current Playwright case exercises a browser or live application/API boundary; no pure, in-memory, or raw source-text contract remains in Playwright collection.
- 31 unit files contain 111 declarations and 111 cases, including product-appearance-defaults.test.ts, twelve new Blob/database/cache-teardown infrastructure cases, one new storefront-ordering behavior case, one new product-detail route-cache regression contract, four order-submission latency and recovery contracts, and five order-access transport-security contracts. Eighty-seven cases moved from Playwright during this optimization and the defaults case had moved earlier; none was deleted.
- Across both runners, 229 declarations generate 230 retained cases because one responsive Playwright declaration expands to the 1440 px and 1600 px cases.
- The current product/storefront slice contains 27 E2E declarations and 28 Playwright cases, all browser/API cases. A further 64 product/storefront cases run under the unit command.
- The category/homepage/navigation slice contains 71 E2E declarations across 17 feature-first specs and about 93 top-level page navigations. Five pure/source contracts now run under the unit command.
- The remaining GURS, checkout, order-confirmation, and order-access-security E2E slice contains 17 declarations: fifteen browser cases and two live application/API cases. Thirty admin-variant, GURS, checkout-copy, hidden-flag, order-submission, and order-access-security cases run under the unit command.
- The infrastructure unit slice adds twelve cases: four cover production Blob namespace isolation, strict E2E namespacing, invalid namespace rejection, and external-storage blocking; five make destructive database reset fail closed unless its database, live identity, ownership marker, and namespace form the exact isolated per-run target; three prove E2E cache teardown removes only the generated `.next/cache` directory and is safely repeatable.
- The dedicated authentication slice adds three browser/API cases that prove clean unauthenticated, configured-session, and protected-database boundaries exactly.
- No whole test is an exact duplicate. Two assertion blocks are exact duplicates: the footer legal-row border contract in footer-navigation-editor.spec.ts:11-26 and :364-378, and the initial top-bar panel/table alignment checks in navigation-topbar-appearance.spec.ts:163-164 and :203-204.
- No user-facing requirement is proven obsolete by repository evidence. Exact source strings, fixed Tailwind classes, and fixture-count assertions are implementation contracts that should be replaced or derived, not silently deleted.

Runtime estimates below are static estimates for a healthy sequential run with one worker and zero retries. They are based on removed browser navigations, waits, or server dependencies; they are not measurements from the broken 51.7-minute CI run. A value of conditional means the saving exists only after replacement unit, component, visual, or integration coverage is running outside the E2E command.

## Decision rules

- Keep: the case protects a unique end-to-end, API, accessibility, concurrency, no-write, or logical-branch requirement.
- Consolidate: copy every listed unique assertion into the named survivor before removing the redundant declaration or assertion block.
- Move: land equivalent coverage in the recommended layer, prove it passes, then remove the Playwright declaration.
- Move completed: the same titled requirement now runs under tests/unit; this is a layer change, not deletion approval.
- Delete: reserved for a proven obsolete requirement or exact replacement. This audit recommends no un-replaced deletion.
- Split: retain the E2E workflow while moving pure geometry/formatting assertions to component or visual coverage.

## Implemented feature-first split of the former podoba-redesign monolith

The former 3,139-line file was a file-level sharding bottleneck. Its 26 declarations now live in five feature-first specs without test-title or test-logic changes:

| Current spec | Tests | Purpose |
|---|---:|---|
| appearance-landing-category-editor.spec.ts | 11 | Homepage shell, guides, category/footer editing, category persistence and save concurrency |
| homepage-responsive-preview-motion.spec.ts | 3 | Continuous viewport animation, rapid retargeting and reduced motion |
| logo-global-appearance.spec.ts | 5 | Podoba tabs, logo editor, global parameters and legacy redirects |
| topbar-navigation-editor.spec.ts | 5 | Range editing, gutter/offset geometry, save concurrency and defaults |
| footer-navigation-editor.spec.ts | 2 | Focused legal-row contract and nested footer editing/save |

The split raised the feature-level E2E file count by four without changing those 26 declarations. The later browserless migration plus the focused confirmation and order-access security coverage leave 30 E2E specs and 119 generated Playwright cases; twelve newly added Blob/database/cache-teardown safety cases, one new storefront-ordering behavior case, one product-detail route-cache regression contract, four order-submission latency and recovery contracts, and five order-access transport-security contracts bring the current cross-runner total to 230.

Keep one Playwright worker per isolated shard until shared database, analytics, cache, and mutable-storage ownership is proven. Moving browserless contracts out of tests/e2e is more valuable than enabling fullyParallel against shared state.

Highest-confidence browser consolidations are the category public listing pair, the navigation default/layout pair, the homepage-toolbar structural pair, the generic catalogue listing pair, the order mobile-layout pair and the overlapping GURS autocomplete interaction setup. Those are recommendations, not deletion approval: each survivor must first absorb the unique assertions identified in its inventory row.

The product slice now has 64 unit cases and 28 generated Playwright cases; all remaining Playwright product cases exercise browser or live API behavior. Moving the browserless contracts is unlikely to deliver large wall-clock savings by itself because they did not instantiate a page. The clearest remaining browser-start saving is moving the stale specification-write case to authenticated API integration, estimated at 1-3 seconds. Shared authenticated smoke setup may save approximately 2-8 seconds; the more important correction, now represented by the dedicated authentication cases, is to assert login and protected content as separate outcomes.

1. The target unit runner now exists and owns 111 retained cases. There is still no dedicated component or visual command, so rows recommending those layers remain gated.
2. Demonstrate one-for-one requirement coverage using the Behavior and Unique assertions columns, including negative branches, accessibility assertions and persistence/no-write checks.
3. Run the old and replacement tests together at least once, then compare healthy-run timing. Do not use the current failing/auth-blocked run as a runtime baseline.
4. The Playwright project uses global authenticated storage for protected workflows. Anonymous browser/API tests must continue to create explicit clean contexts with empty storage so public and authenticated boundaries remain distinct.
